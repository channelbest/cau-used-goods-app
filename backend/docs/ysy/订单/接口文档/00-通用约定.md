# 订单模块通用约定

## 1. Base URL

```text
http://127.0.0.1:8080
```

## 2. 鉴权

- 创建、确认、取消、完成订单需要登录 + 学生认证 `VERIFIED`
- 查看订单列表和详情需要登录（无需认证）
- 管理员接口需要登录 + `role=ADMIN` 或 `SUPER_ADMIN`

```http
Authorization: Bearer <token>
```

## 3. 统一响应

成功：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-06-09 12:00:00"
}
```

失败：

```json
{
  "code": 400,
  "message": "错误说明",
  "data": null,
  "timestamp": "2026-06-09 12:00:00"
}
```

## 4. 分页约定

列表类接口使用：

| 参数 | 类型 | 默认 | 规则 |
| --- | --- | --- | --- |
| `page` | number | 1 | 小于 1 时按 1 处理 |
| `pageSize` | number | 20 | 小于 1 时按 20，最大 100 |

分页响应：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 20
}
```

## 5. 枚举

订单状态：

```text
PENDING_CONFIRM / WAIT_MEET / COMPLETED / CANCELED / EXCEPTION_CLOSED
```

角色参数：

```text
buyer / seller
```

## 6. 模块职责

订单模块负责处理二手交易的核心交易流程，包括订单创建、卖家确认、订单取消、订单完成等操作，以及订单状态流转和并发控制。

## 7. 关联数据表

- `orders` — 订单主表
- `products` — 商品表（订单操作会修改商品状态）

## 8. 订单状态流转

```
PENDING_CONFIRM（待确认）
    ├── 卖家确认 → WAIT_MEET（待见面）
    ├── 买家/卖家取消 → CANCELED（已取消）
    └── 超时未确认 → CANCELED（系统自动取消）

WAIT_MEET（待见面）
    ├── 卖家完成 → COMPLETED（已完成）
    ├── 买家/卖家取消 → CANCELED（已取消）
    └── 管理员异常关闭 → EXCEPTION_CLOSED（异常关闭）
```

## 9. 核心规则

1. **同一商品同一时间只能有一个有效锁定订单**
2. **创建订单与锁定商品必须在同一个 MySQL 事务中完成**
3. **取消订单与恢复商品必须在同一个 MySQL 事务中完成**
4. **完成订单与标记商品已售必须在同一个 MySQL 事务中完成**
5. **订单创建后 24 小时内卖家未确认，系统自动取消**
6. **订单详情接口严格校验买卖双方身份，防止越权访问**
7. **订单详情和订单状态变更接口保持订单主表快照结构，不直接扩展商品图片字段；前端展示订单商品图时，优先使用订单列表返回的 `productImage`，详情缺图时通过 `tradeService.getOrderWithImage()` 回查订单列表补齐**
8. **商品被订单锁定后，订单买卖双方仍可通过 `GET /products/:id` 查看该商品详情和图片，用于订单详情、交易沟通和售后追溯；未参与订单的普通用户仍不能查看非在售商品**

## 10. 前端错误处理建议

- `401`：清理登录态并跳转登录页。
- `403`：展示权限或账号状态提示，不要重试。
- `400`：展示业务错误提示，如参数错误、商品不可用、状态流转错误等。
- `404`：订单不存在。
- `500`：展示系统异常提示，并记录接口与请求参数方便排查。
